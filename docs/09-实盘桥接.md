# 09 · 从研究到实盘：QMT / 同花顺桥接架构

> 目标：说清「鸿蒙做研究、Windows VM 做实盘」的架构，以及数据如何从实盘端流回鸿蒙研究端。
> **状态声明**：方案与双端脚本已就绪，CSV 管道已 smoke 验证通过；**唯一未实机验证的是券商 miniQMT 权限 + ARM64 VM 实机跑 x64 客户端**。

## 9.1 为什么需要一台 Windows VM

A 股券商程序化交易客户端（QMT / miniQMT / 同花顺）**只发布 Windows 版**。鸿蒙 PC 上的出路：

```
┌─────────────────────────────┐        ┌──────────────────────────────┐
│  HarmonyOS PC（本机）         │        │  Oseasy Win ARM64 VM          │
│                             │        │                              │
│  研究 / 回测 / 可视化          │  共享  │  实盘引擎（只能 Windows 跑）      │
│  · backtrader / vectorbt    │  Documents │  · QMT/miniQMT（迅投）x64     │
│  · rqalpha / pyqlib         │←──────→│    xtquant 拉行情 + 交易        │
│  · akshare 腾讯源（研究数据）  │  CSV   │  · 同花顺（行情终端/手工导出）     │
│                             │        │                              │
│  qmt_consume.py（读桥接 CSV） │        │  qmt_bridge.py（xtquant 写 CSV）│
└─────────────────────────────┘        └──────────────────────────────┘
```

- **QMT / miniQMT（迅投）= 实盘数据 + 交易正道**：官方提供 Python 包 `xtquant`（已上 PyPI），支持行情订阅与下单。
- **同花顺 = 行情终端 + 手工导出 CSV**：零售端无干净本地 Python 实时 API，程序化实盘不靠它。
- **桥接 = VM 内写 CSV → 鸿蒙读 CSV**：研究端数据源切换零改动（腾讯源 CSV ↔ QMT CSV 同构）。

## 9.2 VM 侧：qmt_bridge.py（xtquant 拉数据写 CSV）

```python
# qmt_bridge.py —— 在 Windows VM 内运行
import sys
# xtquant 官方装法：pip install xtquant
# 装不上（如 Python 版本不匹配）则直接指向客户端自带的包：
# sys.path.insert(0, r"C:\国金QMT交易端\bin.x64\Lib\site-packages\xtquant")
from xtquant import xtdata
from xtquant.xttrader import XtQuantTrader, StockAccount

# --- 行情 ---
xtdata.connect()                                  # 默认 127.0.0.1:58610（需先登录客户端）
for code in ["600519.SH", "000858.SZ"]:
    xtdata.download_history_data(code, "1d", "20230101", "20260901")
    df = xtdata.get_market_data_ex([], [code], period="1d",
                                   start_time="20230101", end_time="20260901")
    # ... df 转 CSV（列与鸿蒙腾讯源 CSV 对齐）写到共享 Documents 目录

# --- 交易（需开通 miniQMT 权限）---
trader = XtQuantTrader(r"C:\国金QMT交易端\userdata_mini", session_id=1)
trader.start(); trader.connect()
acc = StockAccount("资金账号", "STOCK")
trader.query_stock_asset(acc)     # 查持仓/资金
# 下单：trader.order_stock(acc, "600519.SH", 100, xtconstant.STOCK_BUY, ...)
```

> miniQMT 要点：① 需券商开通权限（通常资金门槛 5~10 万）；② 代码带后缀 `600519.SH` / `000001.SZ`；③ **miniQMT 不做回测**——回测仍在鸿蒙 backtrader/vectorbt/rqalpha 做，QMT 只负责实盘行情与下单。

## 9.3 鸿蒙侧：qmt_consume.py（读桥接 CSV）

鸿蒙侧与 `momentum_scan.py` 共用同一套分析代码，仅把数据源从 `data/*.csv`（腾讯源）换成桥接目录（QMT 写入的 CSV）——**研究代码零改动**。已用 data/ 腾讯源 CSV 做了 smoke 验证，横截面动量结果与直接腾讯源完全一致。

## 9.4 桥接 CSV 字段对齐

| 字段 | 腾讯源（研究） | xtquant（实盘） |
|---|---|---|
| date | `YYYY-MM-DD` | 对齐为同格式 |
| open/close/high/low | qfq | 建议也取前复权，保证策略一致性 |
| volume | 手 | 股（除以 100 对齐） |

> 复权一致性是实盘接力的最大暗坑：**回测用前复权、实盘用不复权价** 时，策略信号在除权日前后会漂移。实盘端要么全程不复权 + 信号用价格比率（对复权不敏感），要么研究端与实盘端统一复权口径。

| 步骤 | 状态 |
