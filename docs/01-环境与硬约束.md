# 01 · 环境与硬约束

> 这一章决定后面所有操作能不能解释得通。**先读这一章再动手。**

## 1.1 这是一台什么样的机器

HarmonyOS PC（本仓库实测为 HUAWEI MateBook Pro）本质上是 **OpenHarmony + 华为商业套件的 aarch64 电脑**：

- CPU：aarch64（20 核）；内存 31 GB
- 内核 libc：**musl**（`ld-musl-aarch64`），与主流 Linux 的 glibc 不同
- 系统 Python：**3.12.9**，位于 `/data/storage/el1/bundle/libs/arm64/python/bin/python3`（应用沙箱路径，但可直接调用）
- 无 apt / yum / dnf / brew（社区有 HarmonyBrew 可用，但科学计算栈不需要它）

## 1.2 硬性约束清单（实测）

| # | 约束 | 影响 | 对策 |
|---|---|---|---|
| 1 | **禁止符号链接**（任意位置） | `python3 -m venv` 失败（venv 依赖 symlink） | 不用 venv，直接 `pip install --user`；如需隔离用 `pip --target` + `PYTHONPATH` |
| 2 | **无 `/usr/bin/env`** | shebang 写 `#!/usr/bin/env python3` 的脚本直接炸 | 直接调用解释器，或改写 shebang |
| 3 | **`/tmp` 只读** | 很多工具默认往 /tmp 写 | 用 `~/.cache` 或工作目录；pip 缓存改 `--cache-dir`（可选） |
| 4 | **无 gcc/gfortran** | NDK 只有 clang 系；Fortran（OpenBLAS/LAPACK 核心）**编不了** | **绝不现场编译**，只用预编译 wheel（见 §1.4 判定铁律） |
| 5 | **所有 `.so` 必须代码签名** | 未签名的动态库 `dlopen` 报 `signature verification failed` | 装完编译型包后用 binary-sign-tool 逐个签名（见 §1.3） |
| 6 | **用户可写分区大多 noexec** | 工作区（hmdfs）里的二进制/`.so` 无法执行或加载 | 包一律装到 `~/.local`（该分区允许加载已签名 .so）；脚本放工作区没关系 |
| 7 | **无系统 CA 证书库** | `pip`/`curl`/`urllib` 访问 https 报证书错 | 每条命令前 `export SSL_CERT_FILE=/etc/ssl/certs/cacert.pem` |
| 8 | **无系统 curl/git/zsh** | 部分脚本依赖它们 | 用 Python `urllib` 下载；`~/.ohos-tools` 下有鸿蒙版工具 |
| 9 | wheel 平台标签必须为 **`cp312-cp312-ohos_aarch64`** | PyPI 的 `manylinux`/`musllinux` 预编译 wheel 全部装不上（pip 判定平台不匹配） | 见 §1.4 —— 这是"为什么不能直接 pip install scipy"的根本原因 |

## 1.3 代码签名：一切编译型包的门槛

HarmonyOS 对动态库有强制签名校验。`pip install` 装完的 wheel 里每个 `.so` 都要过一遍签名，否则 import 时 `dlopen` 直接失败。

**签名工具**（SDK 自带）：

```bash
SIG=/data/service/hnp/ohos-sdk.org/ohos-sdk_26.0.0.18/ohos/toolchains/lib/binary-sign-tool
# 不同设备的 SDK 路径可能不同，找不到就用这个命令定位：
# find /data/service/hnp -name binary-sign-tool
```

**用法**（注意：`--help` 会被拒，直接用 `sign` 子命令）：

```bash
"$SIG" sign -inFile /path/to/X.so -outFile /path/to/X.so -selfSign 1
```

**一键签名所有已装包的 .so**（每次 pip 装完编译型包后跑一次）：

```bash
find ~/.local/lib/python3.12/site-packages \( -name '*.so' -o -name '*.so.*' \) | while read s; do
  "$SIG" sign -inFile "$s" -outFile "$s" -selfSign 1 >/dev/null 2>&1 || echo "SIGN-FAIL $s"
done
```

> ⚠️ 若某包 import 报 `signature verification failed`，基本就是装完后没签名，或后续操作覆盖了签名段。重跑上面的签名循环即可。

## 1.4 判定铁律：这个包到底装不装得上？

**别再凭"编译型包 = 装不上"一刀切。** 2026 年的 OpenHarmony 社区镜像生态已经相当完整。按以下顺序判定：

```
第 1 步  查 OpenHarmony 社区镜像 simple 索引
        https://pypi.repo.openharmony.cn/artifactory/api/pypi/openharmony-pypi-local/simple/<包名>/
        ├─ 有 cp312-cp312-ohos_aarch64 wheel  →  ✅ pip install --only-binary=:all: --index-url OH_SRC
        └─ 没有 ↓
第 2 步  查 PyPI：这个包是不是纯 Python（py3-none-any）？
        ├─ 是 →  ✅ pip install（与平台无关，直接装）
        └─ 否 ↓
第 3 步  只有 2 个 Cython 扩展 / 少量二进制？ →  ✅ "源码树 + 纯 Python 替换"（本仓库 pyqlib 方案）
        是大型 C/C++/Fortran/Rust 项目且无 ohos wheel？ →  ❌ 真装不上，找替代
```

**已查实有 `ohos_aarch64` wheel 的包**（OpenHarmony 社区镜像收录，全部实测可用）：

> numpy 2.2.6 / pandas 2.2.3（系统预置）
> scipy（见 docs/03，注意选镜像）· matplotlib 3.10 · Pillow 12.2 · h5py 3.16
> numba 0.62~0.67 + llvmlite 0.43~0.49 · scikit-learn 1.8 · lightgbm 4.6.0
> **torch 2.4 / 2.11**（CPU）· lxml 4.9.3~6.1.1 · cvxpy / pyarrow / pymongo / pydantic-core 等

**查实没有（404）的**：`bcolz`（需 c-blosc C 库）、`TA-Lib`（Python wrapper 需要 libta_lib C 库）→ 分别用纯 Python 的 `h5py` / `pandas_ta` 替代。

## 1.5 目录布局约定

| 路径 | 用途 | 可执行/加载 .so? |
|---|---|---|
| `~/.local/lib/python3.12/site-packages` | **用户级包目录（唯一推荐安装位置）** | ✅（签名后可加载） |
| 工作区（hmdfs 挂载） | 放项目脚本/数据/文档 | ❌ noexec，别往这装包 |
| `/data/storage/el1/bundle/libs/arm64/python` | 系统 Python 本体 | ✅（只读，勿改） |

**安装规范**：一切 `pip install` 都加 `--user`（或 `--target ~/.local/lib/python3.12/site-packages`），把编译型包装进 HOME，把脚本留在工作区。
